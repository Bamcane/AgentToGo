AgentToGo
=========
可24小时运行、可插拔、注重隐私的执行者、守护者Agent

AgentToGo试图将AI模型进行实例化、物理化，做一个随插随用、24小时运行的执行者、守护者

这是一个极简纯白方盒子。平时，它是一个24小时开机的小主机。它可以帮你盯住网站、服务、NAS存储池等任何可访问服务，守护你的创造环境。同时我们将Agent视作一个物理实体，将Agent的所有记忆、数据都存储在这块小主机内，即使你更换了电脑、更换了场地，只要插上电源和网线，它就能像原来那样继续回应你、守护你。

不同于传统Agent定时唤醒后让LLM来判断并执行任务，我们允许LLM创建一个定期执行的python脚本，脚本中可以包含任何条件判断，包括但不限于请求API、查看NAS存储池状态等，只有程序判断条件成立，LLM才会被拉起并执行任务，从而实现省Token、强实时性的监测，并保持“用户只需一句话，剩下AI处理”的体验。

## 主题解读

在桌游UNO中，Reverse牌可以反转出牌顺序。我们的循环脚本设计打破OpenClaw等Agent由AI执行Python程序执行任务，变成由循环运行的python脚本判断是否需要执行任务并唤起AI。

Reverse在英语中有反转的意思。我们打破数据上云的传统模式，将它们留在设备本地，让设备就像一个真的数字人在你身边，而不是云上发下来的全息投影。

## Q&A：Desktop Deamon

**一句话**： 一台帮我看守任意在线服务的桌面”小白盒“

**本地云端分工**：机器本地不跑AI模型，通过http网络连接到API，避免本地小模型幻觉与低效的问题。而其他功能（记忆和对话数据、循环脚本执行）完全在开发板中运行。

**技术方案**：使用Python fastapi作为服务器部署在Pi上，使用网页作为用户界面。使用OpenAI兼容接口接入大模型，利用大模型的Tool Calling功能实现记忆、创建任务、发送通知等。

## Q&A：不做第一，做唯一

**为什么是你们做这个？它和你们的痴迷、经历或优势有什么关系**：我们发现，大家似乎都习惯于将自己的数据上传到云端，亦或是直接跑在自己机器上，而Windows有Windows To Go，Linux也有Linux各发行版的To Go。那为什么LLM不能有To Go呢？我是一个很喜欢折腾各Linux发行版的人，当我问起队友：为什么LLM没有To Go的版本？我们都沉思了。可能或许它没有什么价值？可能或许大家已经习惯不去保护自己的隐私。正巧，我的队友中有一个硬件爱好者，因此我们做了它。

**谁是它的真实用户？这几天有没有真人用过它？反馈是什么？**：它的真实用户自然是注重隐私的AI使用者或那些硬件爱好者、ToGo产品爱好者，或者是有监测在线服务需求的人。虽然没有找到其他人使用，但我们组内每个人都将自己代入用户视角体验了一番，尽管它功能的确简陋，但在形态上确实有新意，并尝试了用它监控United Portal什么时候恢复。这个demo没有接入外部通知，如果接入手机、电脑的系统通知，它会更加有用。
